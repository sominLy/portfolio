문제 배경

외국인의 전통시장 불편을 해결한다는 방향만 있었고 무엇을 먼저 풀어야 할지 근거가 없었습니다.

분석 과정

  • 광고·중복 게시글을 제외해 약 7.2만 건으로 정제
  • 감성 가중치와 밀도 기반 클러스터링으로 반복 불편 분류
  • 음식 탐색과 점포 정보 관리 문제를 우선 과제로 선정

기술 한계 · 기능 우선순위 변경

초기 접근

사용자가 올린 음식 사진의 GPS 좌표를 점포와 연결하면 정보를 빠르게 갱신할 수 있다고 봤습니다.

확인한 한계

시장 내부에서는 위치 오차가 커 특정 점포를 안정적으로 구분하기 어려웠습니다.

방향을 바꾼 근거

외국인은 음식명을 모를 때 사진을 먼저 보고 판매처를 찾았습니다. 정밀 위치보다 이미지에서 탐색을 시작하는 흐름이 실제 행동에 가까웠습니다.

실행안

이미지로 음식을 찾고 NFC 키링으로 서비스에 접속하는 흐름을 설계했습니다. 예외 흐름과 우선순위를 포함한 유스케이스 18종과 기능 명세를 작성했습니다.

대학내일 20대연구소

기존 문제

기존 질문은 참여자 관심사 위주여서 사내 제안서가 검토하던 주제와 맞지 않았습니다.

질문 설계

위클리 미팅에서 나온 검토 주제를 아카이빙한 뒤 참여자 관심사와 비교했습니다. 두 자료에 공통으로 나타난 주제를 질문으로 만들었습니다.

분석과 전달

응답을 질문별로 분류해 차트와 요약 문장으로 정리했습니다.

업무 결과

평균 응답률 90% 이상을 유지했고, 6개월간 보고서 20건을 발행했습니다. 일부 내용은 내부 제안서 근거로 활용됐습니다.

이후에는 자료를 수집하기 전에 보고서를 어디에 사용할지 확인하고, 그 결정에 필요한 질문부터 정했습니다.

문제프로젝트마다 고객 요청 방식이 달라 요구사항 누락과 반복 QA가 발생했습니다.
실행일정·기능·디자인 항목을 담은 작업 의뢰서를 만들고, 반복 질문은 QA 매뉴얼로 정리했습니다.

PROJECT 04 · 꽃맵

서비스 맥락

사용자가 꽃 사진과 발견 위치를 공유하면 주변의 개화 정보를 함께 만드는 지도 서비스입니다.

확인한 위험

사진에는 타인의 얼굴이, 파일에는 정확한 촬영 위치가 남아 개인 정보 노출로 이어질 수 있었습니다.

정한 원칙

정확한 촬영 위치가 서비스에 꼭 필요하지 않다고 판단했습니다. 꽃 정보를 찾을 수 있는 주변 범위만 공개하기로 했습니다.

사진을 받을 때타인의 얼굴을 자동으로 가렸습니다.
파일을 저장하기 전에촬영 정보와 EXIF 메타데이터를 제거했습니다.
지도에 공개할 때정확한 좌표 대신 주변 범위로 표시했습니다.
확인한 기준서비스 목적에 필요하지 않은 얼굴과 촬영 위치까지 저장하지 않는 것이 더 중요했습니다.
